Cryptell
OPEN →
A client-side cryptography workbench — AES-GCM, RSA-OAEP/PSS, ECDH key exchange, JWT tooling and password entropy checks, all running in-browser.
WEBCRYPTO · AES/RSA · KEY DERIVATION
Read the case study

The Problem

Most "learn cryptography" resources are either pure theory or copy-paste snippets with no visibility into what's actually happening to the data. I wanted one tool that ran real WebCrypto operations and showed the real output — so the concepts stop being abstract.

The Build

Built entirely on the browser's native WebCrypto API — no external crypto libraries, no backend. Covers symmetric and asymmetric encryption, hashing, HMAC, digital signatures, simulated ECDH key exchange between two parties, PBKDF2/Argon2id key derivation, JWT tooling, and in-memory file hashing/encryption. Keys and plaintext never leave the tab.

Security Decisions

AES-GCM is the default symmetric cipher because it bundles authentication into encryption itself — tampered ciphertext is caught automatically. Every operation generates a fresh IV, since reusing one with the same key silently breaks AES-GCM's guarantees. RSA-OAEP is capped to small payloads by design, which forces the correct pattern: RSA wraps a symmetric key, AES-GCM handles the actual data.

What It Exposes

Building this as a real, usable tool — not a demo — makes the constraints impossible to ignore. IV reuse, RSA's payload limits, why encoding isn't encryption: these stop being trivia and become things the tool has to actively guard against or explain.

Stack

WebCrypto API · Vanilla JavaScript · Client-side only, no backend

What I Set Out To Learn

The practical layer underneath cloud security — networking, Linux, and offensive-security tooling — not just theory. Completed as part of a structured Cyber Security course (CompTIA Security+ track, via 101labs.net).

Labs & Experiments

30 labs across three areas: network diagnostics (traceroute, ping, nslookup, dig, ifconfig/ipconfig, netstat, route, ARP), offensive/recon tooling (Hping, Scanless, dnsenum, Hashcat password cracking, MAC spoofing, WPS attacks via Reaver and Wifite, HTTP credential capture with Wireshark, packet capture with tcpdump), and scripting from fundamentals to advanced (Bash and Python).

Tools Used

What I Learned

Seeing an attack from the tool's-eye view — capturing credentials sent over plain HTTP, cracking a weak hash with Hashcat — makes the reasoning behind security controls concrete in a way reading about them never does.

ElaraPay
OPEN →
An offline-first fintech wallet PWA — virtual cards, bill payments, savings goals and six full themes, built in vanilla JS.
PWA · SERVICE WORKER · FINTECH UX
Read the case study

The Idea

Prove I could design and build a fintech product end-to-end — not a mockup, a fully functional wallet with real interaction logic, positioned as "Wealth, Elevated."

The Build

A PWA, installable to the home screen. Multi-step onboarding, a tiered rewards system (Silver/Gold/Platinum), transfers, bill payments, a tap-to-flip virtual card, savings goals, and a quick-loan simulator with live repayment calculation — across six visual themes.

Offline-First Decisions

Every balance and transaction lives in the browser's local storage — nothing hits a server. That constraint shaped the architecture: every action had to update state instantly and persist locally instead of round-tripping to an API.

UX Decisions

PIN-gated transactions, hidden balance by default, hold-to-copy on the virtual card, streaks and cashback — small mechanics that make a wallet feel alive rather than static.

What I'd Improve

Swap local storage for a real backend — auth and a persisted ledger — to move it from a convincing simulation to a deployable product.

Stack

PWA · Service Worker · Vanilla JavaScript · LocalStorage
